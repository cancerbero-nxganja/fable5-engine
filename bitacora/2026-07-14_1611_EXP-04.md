# Bitácora — 2026-07-14 16:11 UTC — EXP-04

## Qué se hizo

Run 4 del loop. Experimento EXP-04: generar el prompt óptimo para análisis de datos y detección de anomalías, mostrando el razonamiento real (hipótesis consideradas, descartadas y por qué).

Se aplicó el método de EXP-03 (diseño por negación desde el mapa de fallos de EXP-02) a un dominio nuevo. El hallazgo central: el dominio de datos carece del oráculo ejecutable que hace barato el dominio de código (el runtime decide si el código está bien; nada decide si una anomalía es real), así que el prompt óptimo sustituye el oráculo por un **protocolo adversarial**: escalera de artefactos (error de datos → error de pipeline → cambio de definición → evento conocido → casualidad estadística → señal), presupuesto de comparaciones declarado antes de escanear, y asimetría de costos FP/FN que fija el umbral.

Se ejecutó una simulación (obedeciendo la regla de clase A: estadística se ejecuta, no se estima): escanear ruido gaussiano puro con umbral 3σ produce "anomalías" con probabilidad 0.82 con una sola dimensión de 500 puntos, y 1.0 con 20+ dimensiones. El presupuesto de comparaciones pasó de argumento a hecho medido.

La falsificación de la plantilla produjo el refinamiento más valioso: en dominios adversariales (fraude, intrusiones) el "artefacto" puede SER el hallazgo, así que la escalera clasifica pero no filtra — qué peldaños son reportables lo decide la pregunta de decisión.

## Patrones identificados

1. Diseño por negación desde el mapa de fallos: tercera aplicación consecutiva; ya es el método por defecto para "prompt óptimo para X".
2. Detectar la asimetría estructural del dominio nuevo comparándolo contra el dominio ya resuelto (código tiene oráculo; datos no) — más barato que diseñar desde cero.
3. Afirmación estadística propia → simulación inmediata antes de afirmarla (clase A aplicada al propio razonamiento).
4. Descarte por materialización (tercera vez): "reusar plantilla EXP-03" cayó al no poder redactar el bloque Done para anomalías.
5. Escalera de artefactos como diagnóstico diferencial, no filtro.
6. Exploración amplia genera hipótesis, nunca conclusiones; la confirmación exige datos fuera de la búsqueda.
