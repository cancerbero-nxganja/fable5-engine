# Bitácora — Run 3 — EXP-03

**Fecha:** 2026-07-14 14:11 UTC
**Experimento:** EXP-03 — Generar el prompt óptimo para invocar las mejores capacidades de código de Fable 5
**Modelo:** claude-fable-5

## Qué se hizo

Se ejecutó EXP-03 con razonamiento completo visible (documentado en `experiments/EXP-03.md`). El experimento reformuló la pregunta introspectiva ("¿qué prompt te activa mejor?") a su versión respondible ("¿qué prompt neutraliza tus causas observables de mal código?") y derivó el prompt **por negación desde el mapa de fallos de EXP-02**: cada bloque existe porque bloquea una clase de fallo concreta o aporta información imposible de inferir.

Resultado: una plantilla de 6 bloques (Entorno / Contrato con ejemplo concreto / Done ejecutable / Restricciones / Política de supuestos / Libertad de enfoque) en tres variantes (agéntica, chat, exploratoria), con jerarquía de valor marginal: **ejemplo entrada→salida > oráculo ejecutable > entorno > restricciones**. Regla de oro asimétrica: exhaustivo en el QUÉ, silencioso en el CÓMO.

Hipótesis descartadas: incantaciones de rol (no bloquean ningún fallo del inventario), especificación máxima (incrusta el CÓMO → anclaje clase F, y entierra el dato crítico), prompt universal único (el contrato cambia de naturaleza según el tipo de tarea; el invariante real es "criterio de éxito explícito").

## Patrones identificados

1. **Diseño por negación**: derivar artefactos desde el mapa de fallos con criterio de inclusión verificable, no desde folklore de buenas prácticas.
2. **Descartar redactando**: las hipótesis de diseño se refutaron al intentar materializarlas, no argumentando en abstracto — dónde falla la redacción es evidencia más dura.
3. **El oráculo ejecutable como centro**: el código es el dominio donde la clase C (verdad-base externa) tiene solución barata y total (el runtime); el prompt óptimo convierte la tarea en bucle contra ese oráculo.
4. **Ejemplo concreto > prosa**: un par entrada→salida literal cierra la semántica de frontera que toda prosa deja abierta, y funciona como chequeo refutador barato (conexión con EXP-01).
5. **Tercer run consecutivo** con el patrón: reformulación epistémica en paso 0 + falsificación del propio output con refinamiento local. Ambos ya son invariantes del protocolo.
